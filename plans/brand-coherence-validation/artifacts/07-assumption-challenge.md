# Devil's Advocate: Plan Assumption Challenge

## Core Understanding

This plan proposes a 6-experiment validation sequence (Experiments 0-5) to turn a failed hypothesis test into a commercial "Semantic Content Alignment" methodology, building on an existing 800-stimulus calibration dataset and extraction pipeline. The plan is substantially improved over the original idea: it incorporates contrastive fine-tuning to address register dominance, pre-registers metrics before real-document testing, includes baseline comparators, and defines explicit kill criteria. However, the plan's sophistication may mask the fact that several core assumptions remain untested, and the contrastive fine-tuning approach — now the load-bearing element — introduces its own failure modes that are qualitatively different from the original critique's concerns.

## Challenged Assumptions

1. **"Contrastive fine-tuning on 800 LLM-generated stimuli will produce a register-invariant encoder that generalizes to real documents."** This is the plan's single most important assumption and it is entirely speculative. The 800 calibration stimuli were generated by an LLM to be 80-150 words with all core attributes present in every register variant. Contrastive training on these stimuli will learn to ignore the *specific* surface-form differences between LLM-generated marketing copy and LLM-generated regulatory text. Real documents have vastly more diverse register signatures (legal boilerplate, social media slang, Amazon listing formatting, FDA filing structure). The contrastive model has never seen any of these real-world register patterns, so there is no reason to expect it will suppress them. The model may learn to ignore LLM-register artifacts rather than register in general. **Status: implicit assumption, unverified, would invalidate the entire approach if wrong.**

2. **"A sentence-transformer fine-tuned with MultipleNegativesRankingLoss will adequately suppress register."** The plan's primary path (E5-large or Jina v3 fine-tuned with sentence-transformers) uses a loss function that pulls same-product pairs together and pushes in-batch negatives apart. But the 800 stimuli have 80 products x 5 registers x 2 variants = only 800 training examples with 80 unique product identities. The model needs to learn "ignore register, preserve product identity" from 800 examples where register variation is limited to 5 LLM-generated styles. Standard contrastive learning benefits from large-scale diverse training data; 800 examples with 5 register types is unlikely to produce robust register invariance. **Status: stated assumption, unverified. The pass criterion (register probe accuracy < 0.7) is a reasonable gate, but the question is whether this gate can be met at all with the available data.**

3. **"The existing calibration dataset is adequate training data for contrastive fine-tuning."** The plan uses the same 800 stimuli for training AND for metric exploration in Experiment 0. This creates two problems: (a) the contrastive model's training set IS the evaluation set for Part A of Experiment 0, so Part A cannot independently validate the model, and (b) the stimuli were designed for a different purpose (testing the Protocol Layer Hypothesis) and may not contain the variation needed for robust contrastive learning. The plan partially addresses this with Part B (degradation tests), but the degradation tests manipulate the same LLM-generated text rather than introducing genuinely novel inputs. **Status: implicit assumption, problematic. The plan needs a held-out split at minimum.**

4. **"Chunking long documents preserves coherence-relevant information."** The plan proposes chunking documents over 4000 tokens into 2000-token windows with 500-token overlap. But the coherence signal the plan aims to measure is *document-level*: "does this regulatory filing tell the same product story as this marketing page?" Chunking a regulatory filing into overlapping windows and then mean-pooling their embeddings is equivalent to mean-pooling all the tokens — with extra computational cost. If the metric is mean cosine similarity between chunk embeddings, chunks from the same document may have varying coherence with a marketing page (the "Methods" section vs. the "Indications" section), and averaging these chunks obscures which part of the document carries the coherence signal. **Status: stated design choice, but its interaction with the coherence metric is unexamined.**

5. **"The contrastive encoder's embedding space will have the same relationship to 'coherence' as the base Qwen's layer 61 representations."** The original finding was RSA r=0.371 for product identity at layer 61 of Qwen2.5-32B. The contrastive fine-tuning trains a completely different model (E5-large or Jina v3) with a completely different objective. There is no reason to expect the contrastive model's notion of "product similarity" will correlate with the original product-identity signal. The plan effectively abandons the original finding and builds something new. This is not necessarily wrong, but it means the original experiment's results provide almost no evidence for the contrastive approach. **Status: implicit assumption, potentially misleading. The plan presents the contrastive approach as "building on" the original findings, but it is closer to starting over with a new method.**

6. **"Pre-registering the metric in Experiment 0, then locking it, prevents p-hacking."** The metric lock is commendable, but Experiment 0 explores a large combinatorial space: {raw, mean-centered, whitened, contrastive} x {multiple layers for base Qwen} x {mean_pairwise, min_pairwise, centroid_distance, silhouette} x {cosine distance}. With this many degrees of freedom, the "best" combination on the calibration data will likely capitalize on chance. Selecting the highest-effect-size combination and locking it is still a form of overfitting to the calibration distribution. The plan needs either (a) a held-out validation set or (b) a much smaller pre-registered candidate space. **Status: stated design, but the anti-p-hacking intent is undermined by the breadth of exploration.**

7. **"The operational definitions for 'known consistent' and 'known inconsistent' products are objective enough to prevent confirmation bias."** The criteria listed (large brand vs. startup, unified agency vs. multiple agencies, known rebranding) are reasonable but not independently verifiable. "Documented brand guidelines publicly available" is checkable; "social media voice disconnected from packaging" requires the kind of subjective judgment the metric is supposed to replace. More critically, large established brands with strict regulatory alignment (the "known consistent" prototype) also tend to have more corporate boilerplate, standardized formatting, and institutional language patterns — all of which could produce tighter embeddings regardless of messaging coherence. **Status: stated assumption, partially verified (criteria are documented), but confound risk is high.**

8. **"Mann-Whitney U with n=10 per group provides adequate statistical power."** The plan claims power ~0.80 for Cohen's d=1.0. This is correct for a standard parametric scenario, but the actual data will have structure (products within categories, variable document counts per product, variable document lengths) that violates the i.i.d. assumption. More importantly, d=1.0 is a *large* effect size. If the true effect is d=0.6 (medium), power drops to ~0.46, meaning the experiment has a coin-flip chance of detecting a real but moderate effect. The plan should state the minimum detectable effect size at 80% power, not the target effect size. **Status: stated but overly optimistic. The power analysis assumes the best case.**

9. **"The BCI (Brand Coherence Index) 0-100 scale calibrated against the 800-stimulus reference distribution will be interpretable."** The calibration stimuli have all attributes present in every register variant — they represent maximum possible coherence. Real documents will always score lower because channels naturally omit some information. The reference distribution will not have a meaningful "low coherence" end because the stimuli were not designed to vary in coherence. The 0-100 scale will compress all real-world products into the lower portion of the range, making differentiation harder and interpretation counterintuitive ("your BCI is 23 out of 100" — because no real brand achieves the calibration ceiling). **Status: implicit assumption, likely to cause interpretability problems.**

10. **"Consumer reviews concatenated into a single document constitute a meaningful 'channel.'"** Decision #7 separates consumer reviews into a "market coherence" tier, which is sensible. But the plan proposes collecting 5-10 reviews and concatenating them. Concatenation creates an artificial document that no one authored. The resulting embedding will be dominated by the most verbose review. Individual reviews vary wildly in content, quality, and relevance. Mean-pooling across concatenated reviews of varying quality will produce a noisy, hard-to-interpret signal. **Status: stated design, but the aggregation method is unprincipled.**

## Logic Gaps

1. **The contrastive fine-tuning and the partial RSA fallback measure fundamentally different things, but the plan treats them as interchangeable.** The contrastive model produces a register-invariant embedding space. Partial RSA on the base Qwen model statistically removes register variance from the RSA correlation. These operate at completely different levels: the contrastive model changes the representation; partial RSA changes the analysis of a fixed representation. Switching between them in Experiment 0 means the "coherence metric" could be measuring two qualitatively different things. The downstream experiments (1-5) should be designed for whichever approach wins, not designed generically.

2. **The pass criterion for contrastive fine-tuning (register probe accuracy < 0.7) does not ensure register is sufficiently suppressed for real documents.** A probe accuracy of 0.7 (down from 1.0) means the model still classifies register correctly 70% of the time — register is still a major organizing dimension. The criterion needs to be lower (e.g., near chance performance at 0.2 for 5 registers), or the plan needs to demonstrate that 0.7 is sufficient via a quantitative argument connecting probe accuracy to coherence metric reliability.

3. **Experiment 0 Part B tests robustness to degradation but not to domain shift.** Truncating calibration stimuli to 20 words simulates short social media text *structurally*, but the content is still LLM-generated calibration text about hypothetical product attributes. A 20-word truncation of "Colgate Total provides 12-hour antibacterial protection with stannous fluoride 0.454%" is not the same distribution as a real tweet: "Just tried Colgate Total and my mouth feels SO clean omg." The degradation tests measure sensitivity to length/attribute-removal within the training distribution, not transfer to a genuinely different distribution.

4. **The plan does not specify how the contrastive model handles the base Qwen's role in Experiments 2-5.** If the contrastive encoder (E5-large or Jina v3) wins in Experiment 0, then the base Qwen2.5-32B model is no longer used. But the plan still references base Qwen for the "Voice Consistency Score" (Phase 2) and for partial RSA fallback analysis. The existing extraction pipeline (`extraction.py`) is built around Qwen's architecture. How does the contrastive encoder integrate with the existing HDF5 storage, hook-based extraction, and layer-wise analysis? The plan lists this as "EXTEND extraction.py" but the contrastive encoder has a single embedding layer, not 64 layers. The integration is more complex than presented.

5. **The value-added test (hidden-state AUC must exceed baseline by >= 0.05) is too weak.** An AUC difference of 0.05 is practically meaningless: with n=20, the confidence interval around each AUC estimate is likely wider than 0.05. The plan cannot statistically distinguish the hidden-state method from baselines at this sample size. Either the threshold needs to be higher (e.g., 0.15) or the test needs a formal statistical comparison (e.g., DeLong test for AUC comparison).

6. **Experiment 3's synonym/paraphrase test does not address the fundamental concern.** The critique noted that attribute probes might work via keyword overlap. The plan proposes testing "whether probes using synonyms/paraphrases (not identical keywords) still show high similarity." But if the contrastive model was trained on 800 stimuli that use specific attribute language (e.g., "stannous fluoride"), it will have learned that vocabulary. A synonym test using "tin fluoride" would test whether the model understands chemistry, not whether it measures coherence. The deeper issue — whether the attribute drill-down is measuring semantic similarity or lexical similarity — requires a control condition where the probe mentions the correct attribute for the *wrong* product and checks that similarity is low.

7. **The timeline estimates do not account for document collection effort.** The plan estimates 53-77 hours of implementation but lists document collection as "2-5 days" separately. Collecting 3-5 real documents from distinct channels for 20 products means sourcing 60-100 documents, cleaning them, verifying channel labels, and handling edge cases (multi-product pages, unavailable channels). In practice this is likely 40-80 hours of manual work — comparable to the entire implementation effort — and is on the critical path for Experiment 1.

## Failure Modes

1. **Contrastive fine-tuning produces representation collapse.** (Impact: HIGH, Likelihood: MEDIUM) With only 800 training examples, the contrastive model may collapse all representations to a narrow region of embedding space, losing all discriminative signal. The plan includes a collapse check, but if collapse occurs, the fallback (partial RSA on base Qwen) returns to the original problem of register dominance without the contrastive solution.

2. **The contrastive model suppresses register on calibration data but not on real documents.** (Impact: HIGH, Likelihood: HIGH) The model learns to ignore the specific register patterns in LLM-generated text (formal vs. casual vs. journalistic) but has never seen Amazon listing formatting, FDA filing boilerplate, or real tweet syntax. Real-world register variation is orders of magnitude more diverse than the 5 LLM-generated styles. The register probe accuracy test in Experiment 0 is measured on calibration data, not on real documents — so this failure mode is undetectable until Experiment 1.

3. **Experiment 1 passes, but for confounded reasons.** (Impact: HIGH, Likelihood: MEDIUM) "Known consistent" products are systematically different from "known inconsistent" products on dimensions other than coherence: brand maturity, category regulation level, documentation completeness, vocabulary sophistication. The metric captures one of these confounds. With n=10 per group, there is no statistical power to control for confounds. The face-validity check (2-3 professionals) is too informal to catch subtle confounds.

4. **The locked metric from Experiment 0 fails on real documents, and pre-registration prevents correction.** (Impact: MEDIUM, Likelihood: MEDIUM) Experiment 0 selects the best metric combination on calibration data. Real documents have different characteristics (length distribution, vocabulary, formatting). The locked metric may be suboptimal for real data. The plan correctly identifies this as a trade-off (T2) and says the response is a new Experiment 0 iteration. But each iteration costs 6-8 hours plus the psychological cost of admitting the lock was wrong. In practice, the temptation to "just adjust a little" will be strong.

5. **Long-context encoder choice creates an irreversible dependency.** (Impact: MEDIUM, Likelihood: LOW) The plan evaluates encoder candidates (Jina v3, E5-large, BGE-large) in Experiment 0 and locks the winner. All subsequent experiments use this encoder. If a better encoder becomes available after Experiment 1, switching requires re-running everything. The plan acknowledges model version pinning (M9) but underestimates the switching cost during the validation phase itself.

6. **Expert validation in Experiment 5 conflates familiarity with accuracy.** (Impact: LOW-MEDIUM, Likelihood: MEDIUM) Experts asked to rank brands by coherence will draw on their general knowledge of brand quality, marketing spend, and market position — not just messaging coherence. A well-known brand with high marketing spend will be rated as "more coherent" by default. The metric may agree with experts because both are proxy-measuring brand investment, not messaging coherence.

## Alternative Approaches

**The plan should run a quick "smoke test" before building any infrastructure.** Take 2 real products (one large established brand, one startup), collect 3 documents each from different channels, run them through the existing Qwen2.5-32B pipeline with partial RSA (already implemented in `analysis.py`), and see if the results are directionally sensible. This can be done in 2-4 hours with zero new code. If the raw signal is completely useless on real documents, then building a contrastive fine-tuning pipeline (8-12 hours), an ingestion system (4-6 hours), and a metrics module (3-4 hours) before discovering this is wasteful. The plan's Experiment 0 is on calibration data, not real data — the smoke test fills the gap between Experiment 0 (calibration) and Experiment 1 (full 20-product study).

**Consider using the contrastive model to directly predict coherence rather than treating its embeddings as features for a distance metric.** If the contrastive model is trained with the right objective (pull same-product cross-register pairs together, push different-product pairs apart), the cosine similarity in its embedding space IS the coherence measure by construction. But the plan then adds layers of indirection (mean pairwise aggregation, z-score normalization, 0-100 BCI scale) that may lose the signal the contrastive model was designed to produce. Simplify: coherence = mean cosine similarity between channel embeddings in the contrastive space. If this does not work, the additional complexity will not help.

## Sycophancy Check

The plan incorporates nearly every suggestion from the Phase 1 critique — contrastive fine-tuning (alternative #3 from the critique), baselines (gap #3), pre-registration (gap #2), register correction (gap #1), and n=20 (gap #6). This comprehensiveness is admirable but also suspicious: the plan may be optimizing for "addresses all critique points" rather than "solves the problem." Several of these additions create complexity without clear evidence they are needed:

- The two-tier (brand coherence + market coherence) reporting adds scope and implementation effort but is untested and may confuse rather than clarify.
- The Voice Consistency Score (Phase 2) is explicitly deferred but still shapes the architecture, adding mental overhead.
- The 6-experiment sequence (up from the original 5) is thorough but means the project cannot produce a definitive yes/no answer for 3-5 weeks. A faster, rougher validation (the smoke test above) could provide a go/no-go signal in a day.

The plan is also not interrogating its own premise hard enough: the core claim is that LLM hidden-state geometry encodes something about "semantic content alignment" that simpler methods do not. The original experiment's 100% BoW classification accuracy suggests that surface features are powerful in this domain. The plan includes baselines but treats them as a check to pass, not as the null hypothesis. The correct framing is: "We assume the contrastive-encoded hidden-state approach adds value over TF-IDF. If it does not, we adopt TF-IDF." The plan says this in the failure protocol but the implementation effort is structured as if the hidden-state approach is the default winner.

## Overall Assessment

This plan is well-engineered and intellectually honest in its structure — the sequential gating, the pre-registration, and the explicit kill criteria are genuine strengths. However, its central technical strategy (contrastive fine-tuning on 800 LLM-generated stimuli to produce a register-invariant encoder) introduces a new, untested dependency that carries as much risk as the register-dominance problem it aims to solve. The contrastive model has never seen real-world document register variation, the training data is small, and the evaluation of register suppression occurs on the same distribution as training. The plan should be preceded by a minimal real-document smoke test (2-4 hours, zero new code) to verify that the existing pipeline produces any directionally useful signal on real data before investing 53-77 hours in infrastructure. If the smoke test fails, it reframes the project from "validate and refine" to "fundamental research into whether hidden-state geometry encodes coherence at all" — a worthwhile reframing that saves weeks of premature engineering.
